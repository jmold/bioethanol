# V0.20 Connected Plant Engine — Release Candidate Status

## Implemented

- Connected discrete-event engine in `connected_dynamic_engine.py`.
- **No intermediate buffer vessels are assumed.**
- Direct Pretreatment → Hydrolysis and Hydrolysis → Fermentation transfers.
- Partial direct filling is supported where upstream and downstream batch sizes differ (for example 50 t Pretreatment batches accumulating into 100 t Hydrolysis vessels).
- Explicit `STARVED`, `BLOCKED`, `FILLING`, processing, `EMPTYING`, `CIP_TURNAROUND`, and `AVAILABLE` states.
- One shared inlet and one shared outlet transfer-pump resource per batch section.
- Pump contention accounting.
- End-to-end completed feed throughput and annualised ethanol output from completed batches.
- Source-inventory conservation check.
- Legacy V0.19 scheduler retained internally as the chemistry/utility comparison basis.
- `/api/connected-plant` and `/api/v020-meta` endpoints.
- Normal `/api/run` and `/api/dynamic-plant` return the V0.20 connected dynamic payload.
- Desktop and Windows development launchers load the V0.20 API extension.
- Regression tests cover direct hand-off, partial filling, source conservation, starvation, blocking, pump contention, vessel inventory limits and completed throughput.

## Digital Twin

The Digital Twin has been aligned with the current reference process flow:

1. Miscanthus + process water / Feed Preparation
2. Feed Transfer Pump
3. Pretreatment Feed Heat Exchanger
4. Pretreatment
5. Hydrolysis
6. Fermentation
7. Solids Separation
8. Beer Conditioning & Preheat
9. Beer Column
10. Rectifier
11. Molecular Sieve
12. Distillation Utility Envelope
13. Anhydrous Ethanol Product

Side streams shown separately are Fermentation CO2 Vent, Residue Solids, Beer Column Bottoms, Rectifier Bottoms and Sieve Recycle.

Pretreatment, Hydrolysis and Fermentation use event-resolved connected vessel states and actual calculated vessel inventory fractions. Downstream separation and recovery units remain explicitly labelled as continuous engineering-screening blocks until dedicated dynamic models are implemented.

## Model boundary

Reaction chemistry, thermodynamics and utility calculations remain based on the validated steady-state/V0.19 engineering model while V0.20 changes plant scheduling and material hand-off behaviour. This avoids claiming transient reaction kinetics or stage-by-stage recovery dynamics that have not yet been calibrated.

## Release gate

Before publishing V0.20:

- complete Python regression suite must pass;
- frontend production build must pass;
- direct-transfer source inventory closure must remain effectively zero;
- no buffer-vessel assumption may appear in the engine, tests or Digital Twin;
- PR must be mergeable.

After those checks pass, merge to `main`, promote the application/model version, tag the Windows release and allow the signed updater workflow to publish the installer/update metadata.
