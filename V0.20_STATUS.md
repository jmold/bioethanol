# V0.20 Connected Plant Engine — Alpha Status

## Implemented

- Connected discrete-event engine added in `connected_dynamic_engine.py`.
- Causal pretreatment → hydrolysis → fermentation batch hand-offs.
- Finite pretreatment/hydrolysis and hydrolysis/fermentation buffers.
- Explicit `STARVED`, `BLOCKED`, `FILLING`, processing, `EMPTYING`, `CIP_TURNAROUND`, and `AVAILABLE` states.
- One shared inlet and one shared outlet transfer-pump resource per batch section.
- Pump contention accounting.
- End-to-end completed feed throughput and ethanol production derived from completed batches over the simulation horizon.
- Source-inventory conservation check.
- Legacy V0.19 independent scheduler retained for comparison.
- `/api/connected-plant` and `/api/v020-meta` endpoints.
- The normal V0.20 `/api/run` and `/api/dynamic-plant` paths now return the connected dynamic payload, so the existing Operations and Digital Twin views consume causal vessel states automatically.
- V0.19 dynamic utility values are retained on the common time grid during alpha so the connected scheduling change does not silently rewrite the validated heat/electrical basis.
- Desktop and Windows development launchers load the V0.20 API extension.
- Regression tests cover inventory bounds, source conservation, causal hand-off, starvation, blocking, shared-pump contention, completed throughput and API integration.
- GitHub Actions validation runs the complete Python regression suite and frontend production build.

## Current alpha boundary

The connected engine tracks hydraulic wet mass and source-feed-equivalent mass through the batch train. Reaction chemistry and utility calculations still come from the validated steady-state/V0.19 engineering model. This deliberately avoids claiming transient reaction stoichiometry that has not yet been calibrated from the miscanthus trials.

The existing Digital Twin now receives real connected vessel states and genuine transfer-state timing through the normal run endpoint. However, its vessel liquid-level interpolation is still based on the older representative-cycle visual calculation, and it does not yet draw the two intermediate buffer vessels. The Operations page also does not yet expose the new connected-throughput, starvation, blocking, buffer-utilisation and pump-utilisation KPIs.
